# 1–2 分钟演示脚本（待真实录制）

本文件是拍摄指引，不是已经录制的视频。使用另一台相机/手机同时拍到：被测手机物理屏幕、电脑上的副屏/终端。不要把电脑模拟器当成同一台手机。

## 录制前

1. 先完成部署、离线测试、设备/日历资格验收；确认能在本机加载固定客户端。密钥输入及日历账号选择不进镜头。
2. 用规则模式 `plan` 核对示例日期。任务固定为普通日历＋设置页面，不添加提醒、邀请、中文 GUI 或抖音发送。
3. 主屏进入无敏感内容的短信草稿并显示键盘；屏幕中不出现私人会话。电脑关掉与演示无关的窗口。摄像机对准两个屏幕，避免拍入 API 密钥。
4. 设置“关于手机”可能显示 IMEI 等标识；录制时避开这些字段或在发布视频中明确做隐私遮挡。不能把遮挡当成已修改实际模型上传画面；GUI 原型仍会把该副屏截图发往模型服务。

## 镜头安排（建议，不保证固定耗时）

- **开头约15秒**：说明“同一台安卓手机，电脑只做大脑与显示代理；用户主屏不交给 Agent”。展示自然语言任务和两条路由解释。
- **中段约60–90秒**：运行下方命令，核对真实目标后授权。倒计时回手机持续打字。日历由 Provider 写入，不打开主屏日历。继续依脚本提示，在 GUI 阶段保持打字，电脑副屏由 AutoGLM 滑动/点击进入关于手机。
- **结尾约15秒**：副屏关闭，终端显示两个结果及验证。任务结束后用户自行打开日历查看事件，说明该查看发生在 Agent 完成之后。

```sh
python3 run.py router run '明天下午4点安排30分钟的「交付演示」日程；打开设置，进入关于手机页面' --planner llm
```

优先连续实拍。若模型延迟导致超过2分钟，可提交明确标注剪辑/加速的短片并保留完整原片；不能把暂停、手动接管或多轮拼接伪装成连续无人干预成功。脚本要求返回电脑确认的阶段须如实展示；不要声称“完全无需人工确认”。

## 演示口播

“Wellphone 的重点不是让大模型接管主屏，而是先理解目标，再按已验证的能力路由。日历走系统 Provider，确实需要界面的任务才进入同机副屏。电脑上的规划模型没有直接获得 shell 权限；执行前有人核对，执行后看目标状态和主屏观测。今天展示的是这台 HONOR/Android14 的已验收范围，不代表所有手机和应用。”

## 可展示但不要当主线的内容

抖音固定 ASCII 草稿输入：可展示已记录的结论，实际私聊截图不公开打包；未验收发送。Web 学习计划：代码和设计说明，不宣称新版已完整写入手机。中文试验：一次真机字符映射预检不支持“你好”，未实际输入或发送，不继续尝试。
