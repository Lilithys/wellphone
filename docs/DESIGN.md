# 当前架构与技术取舍

> 下文记录此前自动化尝试。新JSON流程首请求解析失败后，根入口已接回旧监督执行器；当前只解析联系人＋固定数字1，保留操作者导航和核对。以 [当前入口说明](BASELINE-ENTRY.md) 为准。

## 命令即授权，权限仍由执行器限定

根入口从自然语言单句解析实际联系人和内容，不使用固定昵称，也不让截图内容修改任务。当前解析器是可审查的有限语法，不是任意意图理解；不确定指令在连接手机前拒绝。

新执行路径：`run.py` → `delivery_task.py` → `experiments/douyin/run.py auto` → `work/run_douyin_auto.py`。旧 `run_douyin_test.py` 不作为流程入口，只复用其中的显示/音频会话和机器保护。历史DeepSeek、日历、设置与Web保留，均不进入本任务。

## 分层

1. **授权**：本条CLI明确指定对象和内容，按用户授权无需再次询问；不是任意后台消息发送权限。
2. **视觉理解**：AutoGLM返回严格JSON观察，不直接输出shell或任意工具。字段、阶段、对象、草稿、坐标与预算不匹配就停，不自动修复为动作。
3. **执行**：固定阶段状态机：首页→消息列表→目标会话→输入→发送→核验。仅允许限定点击、列表滑动及安全ASCII定向输入，不切换输入法/剪贴板。
4. **隔离**：同一手机的非PRESENTATION虚拟显示，沿用原焦点补丁、原生帧与5fps配置；主屏Activity、键盘与输入法仍由机器监测。
5. **状态**：任务/收件人哈希日志分别记录输入、发送、核验；动作前持久化，未知结果不重试。新请求ID不能绕过未决收件人。
6. **结果**：对比发送前后图，识别新增己方消息并检查草稿清空。模型核验不是独立身份认证/服务端收件证明，机器采样也不是体感零干扰证明。

## 为什么不只是删除input()

人工核对原来承担页面、对象、内容和发送结果判断。新路径用严格模型观察、前后图比较、系统编辑框归属检查与持久日志替代交互，不预填yes，不伪造“用户确认”。仍可能因视觉误识别失败，移除审批不能自动使原型成为通用可靠产品。

## 复用与未解决问题

副屏焦点/音频保护和定向ASCII沿用既有实现。此前客户端层级读取失败，在新授权流程允许同一UID/Activity/窗口/副屏范围只读复查一次；完整性、归属和真实焦点仍必须通过。

模型只读到本机新接收的原生帧；本机PNG更新时间不等于设备捕获时间，队列滞后未获得端到端时间戳证明。昵称可能同名或截断；模型须拒绝，但不是全局唯一账号校验。新的自动全流程和更广ASCII内容尚待真机验收，中文消息预检仍拒绝。

代码导航：`auto_message_policy.py`（协议/持久日志）、`run_douyin_auto.py`（流程/模型/退出）、`douyin_input.py`（系统编辑框）、`douyin_navigation_frame.py`（导航区域连续性）、`run_douyin_test.py:protected_runtime`（清理与音频恢复）。

离线测试使用假设备/模型，覆盖无人工问答、单次输入发送、身份/草稿拒绝、超时保留记录、旧消息不作新结果、预算不足先停等。不能把离线通过当作手机成功视频。
